# ฐานข้อมูลผู้ใช้งานและสิทธิ์

ไฟล์ `001_user_access.sql` สร้างโครงสร้างผู้ใช้งานของ RoietKPS พร้อมบทบาทและสิทธิ์เริ่มต้น ใช้ InnoDB และ utf8mb4 สำหรับ MySQL 5.7 ขึ้นไปหรือ MariaDB 10.2 ขึ้นไป ฝั่ง PHP ใช้ได้กับ PHP 7.4

ขั้นนี้เตรียมฐานข้อมูลเท่านั้น หน้า Login และหน้าข้อมูลเดิมยังเป็นต้นแบบ การตรวจรหัสผ่าน การบังคับสิทธิ์แต่ละคำขอ และการกรองข้อมูลตามผู้ใช้ต้องเชื่อมต่อในขั้นถัดไป

## โครงสร้าง

| ตาราง | หน้าที่ |
| --- | --- |
| `users` | บัญชี รหัสผ่านที่ผ่านการ hash บทบาท สถานะ และหน่วยงานที่รับผิดชอบ |
| `roles` | บทบาทและประเภทขอบเขตข้อมูล |
| `permissions` | สิทธิ์ทำรายการแต่ละประเภท |
| `role_permissions` | จับคู่บทบาทกับสิทธิ์ที่อนุญาต |
| `provinces` | จังหวัดอ้างอิงสำหรับกำหนดพื้นที่ |
| `cooperatives` | ทะเบียนสหกรณ์ขั้นต่ำและจังหวัดที่ตั้ง สำหรับผูกกับบัญชีสหกรณ์ |

หนึ่งบัญชีมีหนึ่งบทบาท รหัส `username` ต้องไม่ซ้ำ โดยเปรียบเทียบตาม collation แบบไม่แยกตัวพิมพ์ใหญ่/เล็ก เก็บรหัสผ่านใน `password_hash VARCHAR(255)` และสร้างค่าด้วย `password_hash($password, PASSWORD_DEFAULT)` เท่านั้น ไม่เก็บรหัสผ่านจริงใน SQL หรือ session

## บทบาทเริ่มต้น

| รหัสบทบาท | ขอบเขต | สิทธิ์เริ่มต้น |
| --- | --- | --- |
| `system_admin` | `none` | จัดการบัญชี บทบาท และสิทธิ์ ไม่มีสิทธิ์ข้อมูลธุรกิจโดยอัตโนมัติ |
| `central_officer` | `all` | ดูข้อมูลทุกพื้นที่ ตรวจคำขอ/เอกสาร และดู/ส่งออกรายงาน |
| `provincial_officer` | `province` | ดูข้อมูลและรายงานในจังหวัด จัดการทะเบียน ตรวจเอกสาร และบันทึกผลติดตามหนี้ |
| `cooperative_user` | `cooperative` | ดูข้อมูลของสหกรณ์ตนเอง ยื่นและติดตามคำขอกู้ |

`loans.review` หมายถึงการตรวจคำขอและเอกสาร ไม่ใช่การอนุมัติเงินกู้ ยังไม่ได้กำหนดสิทธิ์อนุมัติ เบิกจ่าย หรือบันทึกรับชำระ จนกว่าจะกำหนดผู้รับผิดชอบและลำดับงานให้ชัดเจน สิทธิ์ที่ไม่มีรายการใน `role_permissions` ให้ถือว่าไม่อนุญาต

## ข้อมูลสำคัญใน users

| ฟิลด์ | ความหมาย |
| --- | --- |
| `id` | รหัสบัญชีภายใน |
| `username`, `password_hash` | ข้อมูลสำหรับยืนยันตัวตน |
| `full_name`, `email` | ชื่อผู้ใช้งานและอีเมลติดต่อ โดยอีเมลไม่บังคับ |
| `role_id`, `data_scope` | บทบาทและขอบเขต ต้องตรงกับคู่ค่าใน `roles` |
| `province_id`, `cooperative_id` | พื้นที่/สหกรณ์ที่รับผิดชอบ |
| `status` | `pending` รอเปิดใช้งาน, `active` ใช้งาน, `suspended` ระงับ |
| `must_change_password` | เตรียมรองรับการบังคับเปลี่ยนรหัสผ่าน ค่าเริ่มต้น 1 |
| `failed_login_attempts`, `locked_until` | เตรียมรองรับการจำกัดการลองรหัสผ่าน |
| `last_login_at`, `password_changed_at` | เวลาที่เข้าสู่ระบบ/เปลี่ยนรหัสผ่านล่าสุด |
| `created_by`, `created_at`, `updated_at` | ผู้สร้างบัญชีและเวลาสร้าง/แก้ไข |

บัญชีใหม่มีสถานะ `pending` เป็นค่าเริ่มต้น ฟิลด์เกี่ยวกับการล็อกบัญชีและเปลี่ยนรหัสผ่านเป็นเพียงโครงสร้าง ยังต้องเขียนกระบวนการบังคับใช้ในระบบ Login

## กติกาขอบเขตข้อมูล

| data_scope | province_id | cooperative_id |
| --- | --- | --- |
| `none` หรือ `all` | NULL | NULL |
| `province` | ต้องมีจังหวัดที่มีอยู่จริง | NULL |
| `cooperative` | ต้องมีจังหวัดของสหกรณ์นั้น | ต้องมีสหกรณ์ที่มีอยู่จริง |

Foreign Key ตรวจคู่บทบาท/ขอบเขตและคู่สหกรณ์/จังหวัด ส่วน Trigger ตรวจรูปแบบขอบเขตทั้งตอนเพิ่มและแก้ไข ไม่ใช้ CHECK ที่อาจถูกละเลยใน MySQL รุ่นเก่า การเปลี่ยนบทบาทต้องปรับขอบเขตและหน่วยงานให้ตรงกันในคำสั่ง UPDATE เดียว

ข้อกำหนดนี้ป้องกันการผูกบัญชีผิดพื้นที่ การอ่านข้อมูลธุรกิจยังต้องกรองใน SQL ฝั่งเซิร์ฟเวอร์ทุกครั้ง เช่น `WHERE province_id = :province_id` หรือ `WHERE cooperative_id = :cooperative_id` โดยใช้ค่าจากบัญชีที่ยืนยันตัวตนแล้ว ห้ามเชื่อค่าจังหวัด บทบาท หรือสิทธิ์ที่ส่งมาจากเบราว์เซอร์โดยตรง

## นำเข้าฐานข้อมูล

1. เลือกฐานข้อมูลแอปและตรวจว่าไม่มีตารางทั้งหกชื่อข้างต้น สคริปต์นี้ใช้สำหรับติดตั้งครั้งแรก และจะไม่เขียนทับตารางเดิม
2. บัญชีที่นำเข้าต้องมีสิทธิ์สร้างตาราง Foreign Key และ Trigger นำเข้าทั้งไฟล์ผ่าน phpMyAdmin หรือ MySQL/MariaDB CLI เพื่อรองรับ `DELIMITER`

```sh
mysql --default-character-set=utf8mb4 -h localhost -u roietkps_user -p roietkps_db < database/001_user_access.sql
```

คำสั่งจะถามรหัสผ่านโดยไม่ใส่ไว้ในประวัติคำสั่ง สคริปต์ไม่ได้สร้างฐานข้อมูล เลือกฐานข้อมูล หรือเพิ่มบัญชีเริ่มต้น ไม่ควรนำเข้าซ้ำในฐานเดิม หากคำสั่งล้มเหลวระหว่างสร้างตาราง DDL ที่สร้างไปแล้วอาจยังอยู่ ต้องตรวจผลก่อนนำเข้าอีกครั้ง

3. เพิ่มข้อมูลจังหวัดและสหกรณ์อ้างอิงก่อนสร้างบัญชีที่ต้องผูกพื้นที่ บัญชีผู้ดูแลระบบและส่วนกลางไม่ต้องผูกจังหวัด
4. ตรวจสอบผลด้วยคำสั่งด้านล่าง ควรได้ 4 บทบาท 14 สิทธิ์ 25 คู่สิทธิ์ และยังไม่มีผู้ใช้

```sql
SELECT code, name, data_scope FROM roles ORDER BY id;
SELECT COUNT(*) AS permission_count FROM permissions;
SELECT COUNT(*) AS role_permission_count FROM role_permissions;
SELECT COUNT(*) AS user_count FROM users;
SHOW TRIGGERS LIKE 'users';
```

ตรวจสอบข้อมูลเชื่อมต่อใน `config/db.php` ให้ตรงกับฐานข้อมูลที่นำเข้า บัญชี MySQL สำหรับเชื่อมต่อฐานข้อมูลแยกจากบัญชีผู้ใช้งานเว็บในตาราง `users`

## ทดสอบข้อกำหนดฐานข้อมูล

สร้างฐานข้อมูลสำหรับทดสอบโดยเฉพาะ ชื่อต้องขึ้นต้นด้วย `roietkps_test_` นำเข้า SQL แล้วรันทดสอบด้วยตัวแปร TEST_DB แยกจากฐานข้อมูลแอป ตัวทดสอบจะไม่อ่าน `config/db.php` ข้อมูลทดสอบถูก rollback เมื่อจบ แต่ตัวเลข AUTO_INCREMENT อาจเพิ่มขึ้น

```sh
TEST_DB_DSN='mysql:host=127.0.0.1;dbname=roietkps_test_access;charset=utf8mb4' \
TEST_DB_USER='test_user' php tests/user_access_schema_test.php
```

หากฐานทดสอบมีรหัสผ่าน ให้กำหนด `TEST_DB_PASSWORD` ผ่าน environment ของเครื่องมือทดสอบ ไม่เขียนรหัสผ่านไว้ในไฟล์หรือคำสั่งที่บันทึกลงประวัติ

ตรวจการนำเข้าและข้อกำหนดฐานข้อมูลแล้วกับ MariaDB 12.3.2 และ PHP 8.5.2 ผ่าน 24 กรณี ครอบคลุมบัญชีทั้งสี่บทบาท ชื่อผู้ใช้ซ้ำ ขอบเขตผิดพื้นที่ Foreign Key และการแก้ไขบัญชี ยังไม่ได้รันทดสอบโดยตรงบน MySQL หรือ PHP 7.4
